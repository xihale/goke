# S015 MCP：外部 AI 助手管理日程

## 背景与目标

App 不内置 AI。自建同步服务额外暴露一个 MCP（Model Context Protocol）端点，任何 MCP 客户端（Claude、Claude Code 等）用账号令牌连接后，即可结构化地读写该用户的日程数据；写入走与客户端 push 完全相同的记录同步路径，各端自然收敛。

## 非目标

App 内的 MCP 服务端（数据在本地时无稳定入口暴露）；OAuth 授权（沿用 Bearer 令牌）；服务端解析重复展开 / 节次时间（`get_agenda` 只按已落库的记录算）；事件类工具的写操作（日程已并入待办，事件只读历史）。

## 行为

- **端点**：`POST /mcp`，Streamable HTTP 传输，无状态（不维护 Mcp-Session-Id），响应为 JSON；鉴权与同步接口相同（`Authorization: Bearer <token>`），无令牌 401。SDK 为 `github.com/modelcontextprotocol/go-sdk`（v1.8.0）。
- **工具集按 (store, userID) 缓存**：Schema 反射推导每个用户只做一次；`Warmup()` 在服务启动时空构造一遍，Schema 写错让进程起不来，而不是等第一个请求报错。
- **工具**（11 个）：`list_lists`、`create_list`、`get_task`、`search_tasks`、`create_task`、`update_task`、`complete_task`、`delete_task`、`get_agenda`、`search_events`、`list_courses`。输入用 Go 结构体自动生成 JSON Schema 并校验；输出为 JSON 文本；业务错误（记录不存在、格式不对、LWW 被拒）以 `IsError` 工具结果返回，不走协议层错误。
- **写入语义**：MCP 生成的记录 UUID、`updatedAt = now`、`source = CODE`，data 与 App 的 kotlinx 序列化同构（显式写出全部默认值，含 `_t` 判别字段），经 `store.Push` 落库（LWW）；删除写墓碑（wire `deletedAt` 与 data 内 `deletedAt` 同置位）。设备端在打开 App、本地数据变化、登录或手动同步之外，新增**登录状态下的后台周期同步**（WorkManager，15 分钟，网络可用时），外部写入由此到达本机。
- **并发写**：改 / 完成 / 删除走「读 → 变换 → 推」，因设备先写而被 LWW 拒绝时**重读最新版本重试**（至多 3 次）；`delete_task` 幂等（不存在 / 已是墓碑都返回成功），并**级联删除存活的子任务**，与 App 的删除语义一致。
- **与 App 对齐的不变式**：子任务只有一层（父必须顶层；已有子任务的待办不能再变成子任务）；新增按层追加 `sortOrder`（顶层 = 全部待办最大值 + 1，子任务 = 兄弟最大值 + 1，与快速添加 / 编辑页一致）；`dueHasTime=true` 必须已有截止日期。
- **时间**：日期 `YYYY-MM-DD`，时刻 `YYYY-MM-DD HH:MM`（宽容解析，与 App `parseDateTimeLenient` 一致）；带时刻的截止即日程。时区语义与本地模式相同：服务器不换算，App 按本机时区渲染。
- **清除字段**：字符串型（清单、开始 / 截止、排期、父任务）传空串清除；`remindMinutes ≤ 0` 清除；重复 `freq=NONE` 清除。
- **校验**：标题非空；清单 id 必须存在；`blockMinutes` 与 `blockStart` 成对出现；重复参数按 core `Recurrence` 的取值校验。
- **隔离**：所有读取按 userID 过滤，跨用户 id 一律「记录不存在」。
- **漂移防线**：`internal/mcp` 的回放测试用 `core` 的真实记录 fixture（`web-records.json`）驱动全部读取视图——core 模型加字段而 Go 视图没跟上时测试失败。

## 验收

- 无令牌 / 错令牌访问 `/mcp` 得 401；带令牌 `tools/list` 列出全部工具。
- MCP 建清单 + 带时刻待办后，App / Web 同步拉到同一条记录：`_t=task`、`due=…T09:00`、`dueHasTime=true`、`source=CODE`。
- 完成 → 各端 `done=true` 且 `doneAt` 非空；删除父任务 → 子任务墓碑随级联生成，各端活动列表不再出现；重复删除幂等成功。
- 设备先推入更大 `updatedAt` 的版本后，MCP 的旧写入被拒并返回工具错误（不假成功）；删除冲突时重读重试。
- 新增待办的 `sortOrder` 与 App 追加语义一致（顶层全局 max+1，子任务兄弟 max+1）。
- 用户 B 无法读取 / 搜索到用户 A 的任何记录。
